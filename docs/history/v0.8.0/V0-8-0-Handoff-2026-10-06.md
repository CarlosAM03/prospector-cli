# 4. Arquitectura implementada

La arquitectura funcional actual es:

```text
Consumer
    |
    v
ProspectorEngine.search()
        |
        +-- Google Maps Pipeline
        |       |
        |       +-- Navigation
        |       +-- Feed / Summary
        |       +-- Detail
        |       +-- Website Enrichment
        |       |
        |       v
        |   Business[]
        |
        v
Consolidated Source Result
        |
        v
Global Pipeline
        |
        +-- Deterministic Normalization
        +-- Field-Level Recovery
        +-- Issue Collection
        |
        v
SearchResult
        |
        +-- businesses
        |       NormalizedBusiness[]
        |
        +-- original_businesses
        |       Business[]
        |
        +-- issues
        +-- query
        +-- execution_time
        +-- total_found
        |
        v
Consumers
        |
        +-- CLI
        +-- Python
        +-- ExportService
                |
                +-- CSV
                +-- XLSX
```

El wrapper histórico:

`search_businesses()`

también atraviesa la misma frontera global de normalización.

## 4.1 Garantías implementadas

La implementación:

1. Mantiene los doce campos aprobados.
2. Conserva el original consolidado.
3. Construye NormalizedBusiness independiente.
4. Preserva el orden.
5. Preserva la cantidad.
6. Evita deduplicar accidentalmente.
7. Ejecuta una sola normalización por búsqueda pública.
8. Utiliza reglas deterministas.
9. Conserva campos ambiguos.
10. Emite SearchIssue recuperables.
11. Mantiene CSV y XLSX con siete columnas.
12. Mantiene las responsabilidades del scraper Google Maps.

La comparación entre `Business` y `NormalizedBusiness` está protegida mediante pruebas controladas.

## 4.2 Exclusiones respetadas

No se implementaron:

- Multi-query.
- Deduplicación.
- Merge.
- Batch.
- Concurrencia.
- Browser pooling.
- Persistencia.
- API.
- FastAPI.
- Jobs.
- CRM.
- Nuevas fuentes.

Estas capacidades siguen fuera de `v0.8.x`.


Este es el principal caso puntual que conviene revisar.

La segunda ejecución parece contener información de dirección dentro del campo categoría, mientras que la dirección quedó ausente.

La normalización convirtió el campo existente a mayúsculas, conforme a su política, pero no tiene autorización para inferir que esa categoría es realmente una dirección.

**Interpretación:**

Es un posible problema de extracción, parsing o enriquecimiento, no evidencia de que el normalizador haya reconstruido incorrectamente el registro.

La investigación debe dirigirse al componente productor de Business.

No modificar reglas globales de normalización para corregir un caso de clasificación de origen sin evidencia adicional.

La segunda ejecución reportó:


La existencia de estos errores recuperables no constituye una ejecución fallida.

Sin embargo, la fidelidad de identidad continúa siendo prioritaria para la estabilización de Google Maps.

## 7.3 Website enrichment

La ejecución de 75 negocios incluyó casos importantes previamente contemplados por ADR-008.

## 14.3 Decisiones todavía abiertas

### A. Contrato público

Definir si se utiliza:

```python

```

o una interfaz coordinadora independiente.

Preservar compatibilidad de:

```python
ProspectorEngine.search(...)
```

### B. Estrategia de ejecución

Opciones:

- Secuencial.
- Paralela.
- Concurrencia limitada.

No adoptar paralelismo sin medir consumo de recursos.

### C. BrowserRuntime

Evaluar:

- Navegador por consulta.
- Reutilización controlada.
- Contextos separados.

No introducir browser pooling preventivo.

### D. Identidad empresarial

Determinar evidencias y confianza necesarias:

- Nombre.
- Dirección.
- Teléfono.
- Website.
- Identidad de origen.
- Combinaciones verificables.

No deduplicar únicamente por nombre cuando exista riesgo de homónimos.

### E. Merge

Definir:

- Prioridad de campos.
- Conflictos.
- Procedencia.
- Datos originales.
- Trazabilidad.
- Resultados incompletos.

El merge no deberá inventar información.

### F. Resultado global

Definir:

- Resultados por consulta.
- Resultado consolidado.
- Conteos.
- Registros descartados por deduplicación.
- Identidad y procedencia.
- Incidencias.
- Tiempos.

### G. Recuperación multi-query

Ejemplo:

```text
Query A: SUCCESS
Query B: FAILED
Query C: SUCCESS
```

La operación deberá tener una política explícita para resultados parciales.

### H. Observabilidad

El Engine podrá exponer datos útiles para consumidores externos.

No deberá incorporar:

- ProspectingJob.
- FastAPI.
- Base de datos.
- CRM.
- Orquestación SaaS.

Los futuros consumidores definirán sus propias operaciones.
